# Integration Strategy

## Integration Principles

- Each provider integration must have a clear adapter boundary.
- Sandbox and production must be explicitly configured.
- Live integrations must never be faked.
- Provider callbacks must be verified and idempotent.
- Provider failures must leave internal state reviewable.

## Provider Adapter Pattern

Each integration should expose:

- Configuration object.
- Request builder.
- Response parser.
- Error mapper.
- Signature/auth verifier.
- Status check method.
- Reconciliation method where applicable.

Domain services should depend on provider interfaces, not raw HTTP calls.

## Mobile Money

Providers:

- Airtel Money.
- MTN MoMo.

Required flows:

- Collection.
- Disbursement.
- Status check.
- Callback handling.
- Reconciliation.
- Exception handling.

Rules:

- Internal transaction reference is generated by OpFin.
- Provider reference is stored separately.
- Callback payloads are stored before processing.
- Final success requires verified provider status.
- Duplicate callbacks must not duplicate ledger postings.

## Credit reference, CRB and KYC

Inbound credit scoring/CRB retrieval and outbound credit-information reporting are separate integration purposes.

Outbound reporting must retain:

- dedicated customer reporting consent;
- complete verified identity;
- event/payload hash and idempotency;
- due date;
- attempts/failure reason;
- provider reference.

The configured `CREDIT_REFERENCE_REPORTING_*` adapter must be certified against the applicable authorised mechanism before live use.

### CRB/KYC

Required controls:

- Consent check before request.
- Purpose capture.
- Request/response audit event.
- Redacted provider response storage.
- Retry and timeout policy.
- Manual review path for ambiguous results.

## SMS

SMS should be asynchronous. Store message status and provider reference where available.

Rules:

- Do not log message content containing OTPs.
- OTP messages must use short expiry.
- Delivery failure must not expose OTP or secret state.

## Employer Integrations

Future employer-linked benefits should use:

- Employer identity and permission boundary.
- Employee consent.
- Payroll deduction authorization.
- Reconciliation with employer payroll files or APIs.
- Audit trail for enrollment and deductions.

## Insurance and Investment Integrations

Future modules should support:

- Product catalog sync.
- Quote/premium/order initiation.
- Provider status check.
- Policy/holding record updates.
- Reconciliation.
- User consent and disclosures.

## Error Handling

Provider errors should map to stable internal categories:

- `temporary_failure`
- `invalid_request`
- `authentication_failure`
- `insufficient_funds`
- `provider_rejected`
- `pending`
- `unknown`

Never expose raw provider errors to end users without sanitization.

## Observability

Track:

- Provider latency.
- Provider error rate.
- Callback volume.
- Pending transaction age.
- Reconciliation differences.
- Failed jobs by provider.



## Transaction acknowledgement integrations

Receipt creation belongs to OpFin's post-finality product state. SMS/email/channel delivery is a notification side effect; a notification failure must not roll back an otherwise valid receipt/economic transaction.

## Regulatory integrations

Regulatory reports are generated internally as validated evidence packs. External regulator submission remains a separately authorised operational act unless a future certified integration explicitly implements it.
