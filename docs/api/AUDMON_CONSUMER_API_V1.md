# AudMon Consumer API v1

OpFin exposes a read-only assurance feed at `/api/integrations/audmon/v1`.

Authentication uses `X-AudMon-Key` and `X-AudMon-Secret`. OpFin stores only a SHA-256 secret hash. Provision credentials out of band and restrict them to the minimum Financial Spaces/scopes required.

Endpoints:
- `GET /capabilities`
- `GET /audit-events?after_id=0&limit=100`
- `GET /reconciliation-exceptions?after_id=0&limit=100`
- `GET /revenue-events?after_id=0&limit=100`
- `GET /financial-space-controls`

Cursoring uses monotonically increasing record IDs. Consumers persist `next_after_id` and request the next page. Amounts are integer minor units. Timestamps are UTC ISO-8601 where generated by the API.

The API is intentionally read-only. AudMon does not approve, reverse, write off, disburse, alter ledgers or mutate Financial Space state. Remediation remains in OpFin's governed maker-checker workflows.

Audit metadata can contain operational evidence. Do not grant an AudMon client broader Space access than its assurance mandate. Future v2 should add signed webhook delivery, evidence-document manifests and formal OpenAPI once AudMon confirms its ingestion requirements.
