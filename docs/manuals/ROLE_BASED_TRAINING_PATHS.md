# OpFin role-based training and UAT paths

**Classification:** Controlled internal training reference  
**Reviewed:** 21 October 2026  
**Language:** English (United Kingdom)

These exercises explain current **source-defined** workflows. Train on approved test data and accounts. A visible screen does not mean external financial or provider activation has passed. Every exercise must record its version, environment, actor/Space, observed result and defects.

## Customer and personal-finance learner

1. Sign in with the supported authentication method; check personal context before opening a group/organisation.
2. Navigate Today/Home, aspirations, financial position, learning and financial-health guidance. Explain that a wellbeing snapshot is not a credit decision.
3. Verify visible product suitability and provider/lender disclosures before submitting an application.
4. If a provider response is uncertain, use the original reference and status path instead of repeating a payment.
5. Exercise account/data deletion readiness. Unresolved obligations must not silently disappear.

**Pass condition:** customer understanding, consent and privacy are demonstrated; no non-credit wellbeing data is misrepresented as underwriting or guaranteed eligibility.

## Investment-club maker and checker

1. Select the exact club Financial Space, currency and book. Check member ownership and opening evidence.
2. Submit a contribution or investment instruction using the guided form, with original evidence references.
3. Attempt maker self-approval; it must be denied. A distinct authorised checker previews and approves the exact hash.
4. Interrupt submission, reload or change devices, inspect **Saved requests** and resume the same reference/content hash. Acknowledge after reading the result, not as approval.
5. Try cancelling a submitted request; it must not be treated as unsent. Inspect immutable accounting and a frozen statement.
6. Test former-member own-history and mobile CSV/HTML save/share/print. Opening a system dialogue is not proof of successful delivery.

**Pass condition:** one economic event, exact record ownership, valid independent control and no inferred payment finality.

## Essentials servicing officer

1. Verify the customer, lender, configured product, verified payer wallet and disclosed offer.
2. Examine a synthetic partial repayment under the original allocation policy.
3. Simulate provider delay/lost response. Confirm reserved capacity is retained and the same request reconciled.
4. Review duplicate provider references, contradictory outcomes, explicit reversal and append-only servicing evidence.
5. Confirm reserved financing is not displayed as due debt. Verify unresolved servicing blocks unsafe closure.

**Pass condition:** no duplicate collection, no guessed lender funding/settlement/release, and reconciled audit evidence. Complete provider lifecycles remain subject to separate acceptance.

## Institutional finance / statement reviewer

1. Enter an authorised institutional Space under the correct role and entitlement.
2. Stage a synthetic source export with declared source/time window, currency and control totals.
3. Confirm malformed totals fail and that maker/checker publication is independent.
4. Upload explicitly synthetic CSV/PDF statements; distinguish parsing from authentic issuer verification.
5. Attempt cross-Space access, revoked grants and privacy-suppressed network results.
6. Review frozen report, exceptions, appeal and source-evidence expiry.

**Pass condition:** provenance and unknown fields survive unchanged. No synthetic dataset becomes a live issuer, a verified statement, an approved ECL model or a shared-credit agreement.

## SACCO / organisational officer

Review member/product/guarantor and white-label source journeys only within authorised Spaces. Do not activate regulated deposit-taking, disbursements, custody or custom-hostname routing without the separate institution, DNS/TLS and financial controls. Document each incomplete control in the UAT register.

## Developer and AI integrator

Start with [the API entry point](../../API.md) and [the integrator guide](../../apps/api/docs/api/INTEGRATOR_GUIDE.md). Search public guides, inspect authenticated catalogue with an authorised test role, verify reviewed OpenAPI versus registration-only entries, then test 401/403, tenant isolation, unknown provider outcomes and idempotency. A read-only discovery tool never becomes permission to execute financial operations.

## Evaluation and evidence

A training session must include one positive and one denied/uncertain case for each critical financial workflow. Record the test environment, exact commit, role, source evidence, expected outcome, observed status, screenshot/log reference with sensitive data removed, result and responsible owner. Blockers are not silently labelled passed.
